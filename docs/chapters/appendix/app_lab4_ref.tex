\chapter{Lab~4: CipherStrike --- Instructor Reference}
\label{app:lab4}

This appendix provides the deployment and configuration reference for Lab~4
(Cryptography and Steganography CTF). It is intended for instructors and system
administrators responsible for setting up, resetting, and grading the lab
environment. The student-facing challenge guide is available at
\path{docs/web/docs/labs/lab4/}.

\noindent\textbf{ServerC password derivation:} The ServerC password is not given
directly to students. It is the first 12 hex characters of the MD5 hash of the
concatenation of flags A5 and B5:
\texttt{md5(A5\_flag + B5\_flag)[:12] = fa681b59855d}.
Students must solve modules A and B completely before they can access ServerC.
The decoy password \texttt{D3vOps24!} appears as a false hint in some challenge
materials to test attention to detail.

\section*{Lab Startup Checklist}

\begin{enumerate}
    \item Start all nodes from the EVE-NG web interface in order:
          pfSense $\to$ VyOS $\to$ ServerA $\to$ ServerB $\to$ ServerC $\to$ Defender.
    \item Verify VyOS routing between zones:
\begin{lstlisting}[language=bash]
# From VyOS console
show ip route
# Expected: 10.10.1.0/24, 10.10.2.0/24,
#           10.10.3.0/24, 10.10.4.0/24 all connected
\end{lstlisting}
    \item Ensure the EVE-NG host bridge for Zone-C is active (required for
          direct SSH to ServerC from the EVE-NG host).
          Persistent via \texttt{udev} rule \texttt{99-lab4-bridges.rules};
          restore manually if missing:
\begin{lstlisting}[language=bash]
ip addr show vnet0_5   # Should show 10.10.3.253/24
# If missing:
ip addr add 10.10.3.253/24 dev vnet0_5
\end{lstlisting}
    \item Confirm SSH access to all server nodes:
\begin{lstlisting}[language=bash]
ssh admin@10.10.1.10    # ServerA -- N3xaTech!
ssh sysop@10.10.2.10    # ServerB -- S3cure24!
ssh devops@10.10.3.10   # ServerC -- fa681b59855d
\end{lstlisting}
    \item Verify all challenge files are present on each server:
\begin{lstlisting}[language=bash]
# ServerA
ls /home/admin/mensajes/
# A1_mensaje_interceptado.txt  A2_oracle.py  A2_admin_cipher.b64
# A3_documento_clasificado.txt  A4_mensaje_xor.hex  A5_rsa_challenge.txt

# ServerB
ls /srv/public/uploads/
# B1_oficina_novacorp.png  B2_network_diagram.png
# B3_documento_escaneado.png  B4_novacorp_logo.png  B5_camara_seguridad.jpg

# ServerC
ls /home/devops/retos/
# C1_backup_tapes.jpg  C2_backup_log.b64
# C3_api_token.txt  C3_verificador.py
# C4_ecdsa_signatures.txt  C4_verificador.py
\end{lstlisting}
    \item Verify Python dependencies on each server:
\begin{lstlisting}[language=bash]
# ServerA
python3 -c "from Crypto.Cipher import AES; import gmpy2; print('OK')"
# ServerB
python3 -c "from PIL import Image; print('OK')" && which exiftool steghide
# ServerC
python3 -c "import piexif, hlextend; from PIL import Image; print('OK')"
\end{lstlisting}
\end{enumerate}

\section*{Lab Reset Procedure}

To restore the lab to its initial state after a student session, revert each
server node to its pre-challenge EVE-NG snapshot. The challenge files can
alternatively be re-deployed using the provisioning scripts at
\path{src/eve-ng/configs/nodes/Lab4/} in the project repository:

\begin{lstlisting}[language=bash]
# Re-stage ServerA challenges
bash src/eve-ng/configs/nodes/Lab4/serverA/deploy.sh
# Re-stage ServerB challenges
bash src/eve-ng/configs/nodes/Lab4/serverB/deploy.sh
# Re-stage ServerC challenges
bash src/eve-ng/configs/nodes/Lab4/serverC/deploy.sh
\end{lstlisting}
